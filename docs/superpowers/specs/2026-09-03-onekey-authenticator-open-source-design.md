# 2FA验证器-工具开源整理设计

## 1. 文档状态

- 日期：2026-09-03
- 状态：已完成口头设计确认，等待书面规范复核
- 首次公开版本：`v1.0.5`
- 许可证：Apache License 2.0
- 贡献授权：Developer Certificate of Origin（DCO）

## 2. 目标

将现有“2FA验证器-工具”整理为可以安全公开、独立构建和持续共建的 HarmonyOS 项目。公开版必须保留手机端核心 2FA 能力，同时隔离原应用身份、正式签名、云服务凭据和不公开的穿戴设备能力。

公开版使用新的 Git 历史和独立 Bundle Name。原私有仓库保持不变，继续承载私有版本和原开发历史。

## 3. 仓库与发布模型

### 3.1 仓库角色

三个平台使用相同仓库名 `onekey-authenticator`：

- GitHub：`agiledesign-ai/onekey-authenticator`，主仓库和唯一主要协作入口。
- Gitee：`agiledesign/onekey-authenticator`，只作为同步镜像。
- GitCode：`yunagile/onekey-authenticator`，只作为同步镜像。

Issue、Pull Request、版本发布和贡献讨论以 GitHub 为准。Gitee 与 GitCode 不建立独立开发分支，避免三个平台形成不同代码线。

### 3.2 Git 历史

采用干净快照方案：

1. 从私有工作区生成明确的公开文件清单。
2. 将允许公开的当前工作区状态复制到新仓库。
3. 不复制原仓库的 `.git` 目录、提交记录、远程配置或标签。
4. 公开仓库建立全新提交历史。
5. 三个平台的 `main` 分支和 `v1.0.5` 标签必须指向同一提交。

公开快照包含当前尚未提交的反馈页面实现、路由、资源和测试。原私有仓库的工作区状态不得因整理工作发生变化。

### 3.3 应用身份

- 应用显示名称：`2FA验证器-工具`
- 公开 Bundle Name：`com.agiledesign.onekeyauthenticator.opensource`
- 公开版不复用原正式 Bundle Name、Client ID、证书、Profile 或签名配置。
- 服务卡片、跳转参数和其他硬编码应用标识必须同步切换到公开 Bundle Name。

## 4. 功能范围

### 4.1 保留能力

公开版保留以下手机端功能：

- TOTP、HOTP 与 Steam 验证码生成。
- 扫描二维码和手动输入密钥添加账号。
- 本地 Asset Store 存储。
- 账号导入与明文 JSON 导出。
- 人脸解锁。
- 服务卡片。
- 浅色、深色和跟随系统主题。
- 2FA 使用指南、关于应用、隐私政策和清空账号。
- 反馈页面及邮件应用跳转。
- 华为云空间同步源码，但默认不启用。

README 必须明确说明：导出的 JSON 包含敏感账号信息，用户应自行加密保存，不得将备份文件提交到 Issue 或仓库。

### 4.2 `otp_core` 边界

`otp_core` 同时被手机端和原穿戴端依赖，不能整体删除。公开版保留其中手机端需要的通用部分：

- OTP 算法与验证码引擎。
- Base32、HMAC 和密钥编解码。
- 账号模型与存储接口。
- Asset Store 适配器。
- 剪贴板与其他手机端安全策略。

仅供穿戴设备使用的模型、序列化、同步协议、导出项和测试必须删除。`entry` 对 `otp_core` 的依赖继续保留，并通过构建和单元测试验证。

### 4.3 完整移除穿戴能力

公开版不保留以下内容：

- `wear` 模块及其资源、配置和测试。
- 手机端 `features/wear`。
- `SendToWatchPage` 页面及对应路由。
- 设置页中的手表发送入口。
- WearEngine 元数据、权限和远端应用配置。
- 穿戴同步记录、发送策略和账号转换逻辑。
- 仅验证穿戴模块的 Node 合约测试和 ArkTS 测试。
- 将手表同步描述为公开版可用功能的文档内容。

删除后不得保留空入口、失效路由或只为兼容旧代码而存在的占位实现。

### 4.4 华为云空间

云空间源码允许公开，但必须遵守以下边界：

- 仓库中不存在原应用的真实 Client ID。
- 云空间能力、设置入口和初始化默认关闭。
- 使用一个明确的编译期配置开关控制入口与初始化，不建立多套兼容路径。
- 开发者只有在创建自己的 AGC 项目、配置公开 Bundle Name、填入自己的 Client ID 并主动打开开关后，才能启用云空间。
- 未配置云服务时，本地验证码、导入导出和其他离线功能必须正常工作。
- 配置错误时应返回明确错误，不得静默切换到原应用身份或任何内置账号。

README 提供独立的云空间配置章节，并明确这项能力不随默认源码构建自动启用。

## 5. 配置与敏感信息治理

### 5.1 不进入公开仓库的内容

- 签名密码、密钥库、证书和 Profile。
- 正式 Client ID 与其他平台凭据。
- 开发者机器绝对路径。
- IDE 用户配置、构建产物、缓存和日志。
- 真实 2FA 密钥、二维码、账号数据和导出备份。
- 原私有仓库 Git 历史与远程地址配置。

### 5.2 公开配置

公开仓库提供最小化的示例配置和说明。示例值必须使用明显的占位内容，且不得与真实应用身份相似。开发者本地配置文件加入 `.gitignore`。

签名配置不提供自动替代逻辑。开发者需要调试签名时，应在 DevEco Studio 或本地忽略文件中配置自己的签名信息。

### 5.3 自动检查

仓库提供可在本地和持续集成中执行的边界检查，至少覆盖：

- 原正式 Bundle Name。
- `client_id` 的真实值。
- `keyPassword`、`storePassword` 等签名字段及其值。
- `.p12`、`.cer`、`.p7b`、`.pem` 等敏感文件类型。
- 开发者机器绝对路径。
- `wear` 模块、WearEngine、`SendToWatch` 和手表同步路由。

检查规则允许文档中的安全字段名称和移除说明，但不得允许真实值或可执行穿戴实现通过。

## 8. 实施顺序

1. 对私有工作区做只读清单和敏感信息审计。
2. 先在公开仓库建立边界测试。
3. 复制允许公开的快照和反馈页面未提交改动。
4. 删除穿戴模块和跨模块引用。
5. 精简 `otp_core`，保留手机端通用核心。
6. 更换 Bundle Name 和硬编码应用标识。
7. 移除签名配置、Client ID 和本机路径。
8. 将云空间入口与初始化改为默认关闭。
9. 补齐文档、社区文件、截图和 Star 徽章。
10. 运行静态边界检查、单元测试、合约测试和 HarmonyOS 构建。
11. 对整个公开 Git 对象库执行敏感信息复查。
12. 创建首次公开提交和 `v1.0.5` 标签。
13. 创建并推送三个公开仓库。
14. 核对三平台默认分支、标签、README 图片、链接和徽章。

平台登录、验证码和最终发布确认由仓库所有者完成。整理过程不得保存密码、验证码或临时访问令牌。

## 9. 错误处理

- 如果删除穿戴代码后出现编译引用，必须沿依赖链删除穿戴专用引用；不得恢复穿戴模块或增加空占位实现。
- 如果 `otp_core` 的文件同时服务手机端和穿戴端，应保留手机端通用职责，并删除穿戴专用导出与调用。
- 如果未配置 AGC，云空间入口不显示、初始化不执行；本地功能继续正常工作。
- 如果 AGC 配置不完整但开发者主动启用云空间，构建或运行时必须给出明确配置错误。
- 如果边界检查发现敏感内容，停止提交与发布，修正后重新扫描全部 Git 对象。
- 如果三平台提交或标签不一致，停止发布完成声明，重新同步并核对提交哈希。
- 如果平台要求验证码或身份确认，停止自动操作并交由仓库所有者完成。

## 10. 测试与验收

- 现有 Node 合约测试通过，移除只服务穿戴功能的测试。

构建成功不等同于真机、云空间或应用市场验证。未执行的外部验证必须在发布说明中如实标注。
